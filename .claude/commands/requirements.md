# Requirements

Define clear requirements for a project before building.

## Workflow

### 1. Understand the Goal

Ask: "What are you building?" Get clarity on the core purpose and project type.

### 2. Gather Key Decisions

Use AskUserQuestion for:
- Target audience / users
- Core features (prioritized)
- Visual style preferences
- Technical constraints or preferences

### 3. Define Logic and Behavior

- How should each feature work?
- What happens when users do X?
- Edge cases to consider?

### 4. Visual Style (if applicable)

Offer to generate style preview HTML files. Let the user pick or mix elements.

### 5. Write REQUIREMENTS.md

Create the file with:
- **Goal**, What this project does
- **Users**, Who it's for
- **Features**, Core functionality, prioritized
- **Logic**, How it behaves
- **Visual Style**, Design direction
- **Technical Notes**, Framework, constraints, etc.

Get user approval before proceeding.

## Notes

- Use AskUserQuestion for clean decision-making
- Be thorough but not overwhelming
- This file becomes the spec for building
