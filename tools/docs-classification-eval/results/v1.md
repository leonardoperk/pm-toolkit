## Verdict & next change, the honest reading

**A perfect routing score here is a warning, not a win.** The prediction going in was that
the classifier would miss enhancement-class stories. It missed none. Two explanations:

1. The command's Task A criteria are genuinely good (they *do* list "user-visible changes",
   not just "new feature"), and a capable agent applies them well. Partly true.
2. **The reference set telegraphs its answers.** The story descriptions contain the tells, 
   "same UI, same behavior", "no user-facing change", "user-visible", "changed limit". The
   classifier is being tested on *reading a label*, not on *judging an ambiguous story*.
   This is the dominant effect.

Real Jira stories don't announce their user impact. They say "Refactor NotificationService
to use the new queue" and you must **infer** there's no user-facing surface. This set removed
that inference, so it measures reading comprehension, not classification judgment. A 100%
that comes from an easy test is exactly the "green doesn't mean correct" failure mode this
whole toolkit is supposed to guard against.

**v2 is not a classifier change, it's a reference-set change.** Rewrite the descriptions in
raw-Jira voice: state what changed technically, strip every phrase that labels user impact,
and let the classifier infer. Then re-run. Expected: recall drops, and the misses reveal the
*true* enhancement-blind-spot rate. Only once the set is hard enough to produce errors does
tuning the classifier's rules mean anything.

Secondary v2 item: leave priority alone until routing is stress-tested, 4 boundary calls on
an easy set isn't enough signal to tune against.
